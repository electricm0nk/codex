## Provenance — what this cycle recovers

A prior lane built a 6,590-row corpus-wide ledger with the exact same shape as this one, wrote
"complete" into `kanban.md`, and left the data file untracked; the session exited and the file
was lost (`artifacts/epic-5-forward-plan/bucket_v_widen_infra_cycle_receipt.md`, "What did not
survive the salvage"). That receipt named the loader as safe, generic, tested infrastructure and
named exactly what the next cycle owed: build the actual ledger, and **commit it in the same
cycle that builds it**. This cycle is that rebuild, done independently from the population
figures in `docs/work-inventory.json` and SD-33's own committed oracle artifacts — not from the
lost lane's numbers, which were never trusted as a starting point (they could not be, being
unverifiable without their own source file). The final population **happens to match exactly**
(6,590 dispositioned, 256 corpus-wide V remaining) — a coincidence of the method, not of copying
a number: the ledger population and remainder are set-verified against `docs/work-inventory.json`
directly (see Figures below), not against the lost lane's prose.
