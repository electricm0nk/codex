## Wiring, keyed only on the ledger's own per-unit verdict

`apply_bucket_v_oracle_disposition_stamps` gates on `item.verdict.status in
{literal-verified, fixture-verified}` (a unit must already be in bucket V) and then looks up
`item.id` in the consolidated ledger's own `unit_id → (verdict, reason)` map — **never** a shape
predicate or a name list, per the brief's own warning that a shape-only gate already promoted 188
unrelated records in this bundle before being caught pre-commit:

- `verdict == "agree"` → `status = "oracle-agree"`, `reason = None`.
- `verdict == "unverifiable"` → `status = "oracle-unverifiable"`, `reason` carries the ledger's
  own reason text VERBATIM.
- anything else (in particular `"disagree"`) → **untouched**. There are zero `disagree` verdicts
  in the committed ledger today; `disagree_verdict_is_never_dispositioned_and_stays_outstanding`
  (new test) proves a future regen that sees one leaves the unit outstanding in bucket V rather
  than closing it by omission — `decisions.md §19`'s hard constraint.
- a unit whose id is absent from the ledger (the 81 remainder) is left exactly as it was.
- a unit outside bucket V is never touched even if its id happens to appear in the ledger
  (`unit_outside_bucket_v_is_never_touched_even_if_its_id_is_in_the_ledger`, defense-in-depth).

`scripts/completion_atlas.py`'s `_bucket_of` maps both new statuses to `DONE` — `decisions.md
§19` extends `§17`'s ruling that a unit carrying a real, named reason no verdict can be reached is
dispositioned, not outstanding, from bucket `U` to bucket `V`.
