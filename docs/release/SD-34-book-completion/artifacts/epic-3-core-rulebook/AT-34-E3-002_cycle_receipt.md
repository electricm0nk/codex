placed immediately after the pre-existing Favored Terrain display rung
(`src/bin/v06_work_inventory.rs`, `AT-34-E3-002`-tagged comment):

```rust
if let Some(rest) = unit.key.strip_prefix("Monk Unarmed Damage LVL ") {
    if let Some((level_str, size_paren)) = rest.split_once(' ') {
        if let Ok(level) = level_str.parse::<u8>() {
            let size = size_paren.trim_start_matches('(').trim_end_matches(')');
            if facts.monk_unarmed_damage_die_wired.contains(&(level, size.to_string())) {
                return Verdict {
                    status: "grounded",
                    evidence: "monk_unarmed_damage_die_probe_observed_a_real_computed_magnitude".to_string(),
                    reason: None,
                    engine_book: engine_book_field,
                };
            }
        }
    }
}
```

New probe `probe_monk_unarmed_damage_die_wiring` (a NEW probe, unlike the Favored Enemy fix's
reuse of an existing one — no pre-existing `EngineFacts` set covered Monk at all). Run at
**exactly** the corpus record's own band-start level (`[1, 4, 8, 12, 16, 20]`), never
`SWEEP_LEVELS` (`[1, 5, 10, 15, 20]`) — confirmed by reading `monk_unarmed_strike_damage_die`'s
own `min(5, level / 4)` band index directly that `SWEEP_LEVELS` has no member inside the
level-16 band (16-19), so it could never have observed the `"LVL 16"` record at all. The expected
`(face, count)` pair per level is hardcoded from the corpus records' own literal tokens (already
independently re-verified above), mirroring `probe_ranger_favored_enemy_bonus_wiring`'s own
`value == 2` hardcoded check rather than reaching into `pilot_compute`'s private (non-`pub`)
function surface. **Scoped to Medium only** — the probe deliberately never populates a Small
entry, per the cross-book question named above.
