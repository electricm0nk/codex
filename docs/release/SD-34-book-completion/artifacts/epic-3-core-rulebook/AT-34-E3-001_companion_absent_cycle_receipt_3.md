## What was built, and why the class-row and zero-content sub-causes stayed closed

**The 2 monster-class rows (`Companion`, `Shadow Companion`).** Re-checked directly against the
live corpus rows (`cr_classes_companion.lst:6`, `:15`): `CLASS:` rows with `VISIBLE:NO`, an
`HD:`/`MAXLEVEL:` progression, and `BONUS:VAR|Class…` tokens — no `SIZE:`, no `MOVE:`, no
`NATURALATTACKS:`. Modelling this properly needs a genuinely new record type (a level-progression
table) that `CompanionRecord`/`CompanionAbilityRecord` has no fields for and that no other
registered companion book uses either — building one un-verified against a real second consumer
inside this single cycle would be exactly the kind of narrow, unreviewed widening the "verify
against ALL registered books" instruction warns against for Shape 8. Left honestly
`engine-does-not-hold`, named here rather than silently carried forward again.

**The 12 zero-content plumbing rows.** Read the raw corpus token set directly (see
`atlas-defects.md` entry 3): each carries `KEY`, `CATEGORY`, and one-or-more `ABILITY:` grant
tokens routing to real, separately-shipped abilities — no `TYPE:`, `DESC:`, or `BONUS:`. This is a
real, distinct no-content shape from atlas defects 1 and 2 (neither's predicate matches these
rows), re-derived corpus-wide at **461 of 51,482** records across 26 books. Per this cycle's
mandate, it is now RECORDED as a named atlas defect rather than silently left as a bare bucket-B
count — but NOT reclassified: reclassifying by shape alone, without a per-record corpus-wide
check, is the exact near-miss defect 1's own cycle already recorded (188 unrelated records
promoted before being caught pre-commit). Left `engine-does-not-hold`, honestly, with the
disposition question now on record for a future cycle to pick up safely.

**The 14 familiar-pool rows — CLOSED, via Shape 8.** `companion_chassis`'s ownership invariant
required every ability's owner to resolve to a `CompanionRecord` of the SAME book. The 14 rows'
true owners (11 familiar creatures: Bat, Cat, Hawk, Lizard, Monkey, Owl, Rat, Raven, Toad, Viper,
Weasel) are real, already-registered creatures — just under `beastiary`, because Core Rulebook
states the Familiar special-ability rules (Magic chapter, `ce_abilities_familiar_cr.lst`,
`SOURCELONG:Core Rulebook`) while Bestiary states the familiar creature stat blocks
(`ce_races_familiar_cr.lst`, `SOURCELONG:Bestiary`) — a real split the source books themselves
make, confirmed by both prior cycles' own investigation. This cycle built the fix the second
cycle explicitly declined: `companion_chassis` widened with a `cross_book_owners` field, the
transcriber's Shape 8 pass attributes these 14 keys to all 11 `beastiary` familiar creatures
(book-wide within the grant, same discipline as Shape 7's existing book-wide grant), and the
widening was verified against every one of the 16 currently-registered companion books by
regenerating every one of them and diffing for anything beyond the new field (none found — see
Verification below).
