# Criterion 6.1 — UI-eval discovered-defect cycle shape (Epic 6: dynamic-dominant)

- **Concurrency:** serial
- **Subagent tier:** Sonnet
- **Receipt:** `../artifacts/epic_6/defect-cycle-shape_receipt.md`
- **Gated on:** E5 (per loop-instruction §3 epic gating)

## File-touch grant (register C1)

- `progress.md` (`## DISCOVERED` shape definition) + this epic's receipt. No product code in THIS criterion — it defines the shape the 6.2..6.N cycles use.

## Deliverable

Establish and document the per-defect cycle shape:

1. Operator's UI-eval session logs a defect → one `## DISCOVERED` row in `progress.md` (ISO-8601, origin, priority-bump tag, description, suggested criterion `6.<next>`).
2. Dispatcher picks it → one cycle → RED (failing test reproducing the defect) → GREEN (fix) → dual-audit → one receipt at `../artifacts/epic_6/<defect-id>_cycle_receipt.md`.
3. Closure gate: every UI-discovered defect has either a `complete` receipt or an `## Open blockers` entry.
4. Queue cap: `## DISCOVERED` > 10 entries is NON-self-healable (`loop-instruction.md §8`, inherited from SD-24) — stop and surface.

GREEN = the shape is written into `progress.md`'s `## DISCOVERED` header comment + this receipt, and the first real defect row (if any exist by then) conforms.
