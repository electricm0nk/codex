- **Notes / judgment calls:**
  - **Every ACG record this cycle is `source.kind = "lst_token"` — no `web_second_source`/`same_book_fallback`/`lst_corrected_ingest`/`lst_inherited_copy` was needed anywhere, and none was fabricated to fit a schema shape.** Unlike APG (0/338 equipment descriptions have any native LST prose token at all, forcing `web_second_source` for the entire populated field), ACG's `SPROP:`-sourced descriptions and `DESC:`-sourced full-text spell records both trace to a real, checkable corpus line for every populated value. This cycle independently confirmed no `.COPY=`-inheritance chain feeds any of the current `EQUIPMENT_TABLE`/`SPELL_LIST` values either: `acg_equipmods.lst`'s 48 `.COPY=` lines are a separate, already-excluded legacy-key-alias block (per `equipment_tables.rs`'s own doc comment), not a source of any of the 269 live records' field values. Per `decisions.md §11.3`'s own rule ("default `source.kind` to `lst_token` only if a real, checkable LST citation exists for that specific field; otherwise flag it rather than guessing"), an all-`lst_token` cache is the honest outcome here, not a corner cut — the other four discriminated-union variants are still defined in `cache_gen/acg.rs` (Shape B schema parity with `cache_gen::apg`) but marked `#[allow(dead_code)]` since this book's real data never needs them.
  - **Equipmods citation disambiguation by `KEY:` field, not display name.** `acg_equipmods.lst` repeats several display names across distinct `KEY:`-tagged targets — e.g. `Sneaky` appears once for `KEY:Special Ability ~ Sneaky ~ Melee` (real line 47) and once for `KEY:Special Ability ~ Sneaky ~ Amulet of Mighty Fists` (real line 72), with byte-identical `SPROP:` text but genuinely different targets/mechanics contexts. A naive first-column name lookup would silently collapse both onto line 47. This generator instead matches on the tab-delimited `KEY:<entry.key>` field for `EquipmentCategory::Equipmods` records specifically (General/ArmsArmor/MagicItems have no distinct `KEY:` token — `entry.key == entry.name` there, matching `equipment_tables.rs`'s own doc comment — so those still resolve via first-column name match). Verified directly: `tests/sd26_cache_acg.rs`'s `equipment_cache_disambiguates_equipmods_records_sharing_a_display_name_by_real_key_token` asserts the two `Sneaky` records resolve to distinct real lines (47 vs. 72).
  - **A real corpus oddity, "Fake Rapier" (`acg_equip.lst:35`, `SPROP:Tests`), was dumped verbatim, not filtered or special-cased.** Confirmed by direct grep of the live PCGen corpus this cycle to be a genuine upstream row (not a codex-side fixture leak) — this book's `ArmsArmor` category has 20 real records including this one. Per the no-stub-mvp doctrine's "real failure/gap beats fake success" framing, the generator dumps whatever the compiled module and corpus actually contain; it does not curate or exclude oddly-named-but-real records. Covered by `tests/sd26_cache_acg.rs`'s `equipment_cache_includes_the_real_corpus_oddity_fake_rapier_without_special_casing`.
