- **Notes / judgment calls:**
  - **`source` is keyed off the record's most informative field, not a literal per-field breakdown.** Shape B (`decisions.md §7`/§11.2) defines one `source` object per JSON record. Equipment/spell records mix LST-native identity fields (name/cost/weight, school/level) with a `description` field that may have entirely different provenance. This generator resolves that tension by keying `source.kind` off `description`'s real provenance (the field SD-25's corpus-intake work actually closed, and the field `decisions.md §11.2`'s discriminated union was written to represent) — for classes, `source` describes the whole BAB/save chassis instead, since that *is* the record's entire content this pass. Documented at the top of `cache_gen/apg.rs`.
  - **Equipment `web_second_source.url` precision is two-tiered, both real, neither fabricated.** SD-25's `corpus-intake-apg-description` receipt individually names ~35 of the 331 web-sourced equipment records against a specific page; the remaining ~296 were sourced from 10 category-aggregate pages covering "nearly all" of a category without an exhaustive per-item name list, and `equipment_data.rs` itself does not store a per-record source URL (SD-25 worked directly in Rust source). Reconstructing exact per-item URLs for all 331 would mean redoing SD-25's web research from scratch — outside this cycle's "dump the Rust module" charter (`decisions.md §11.3`). This generator instead cites: (a) the exact page for the ~35 individually-named items (`citation_precision: "exact_item_page"`), and (b) the single best-documented aggregate page for the record's `EquipmentCategory` for everything else (`citation_precision: "category_aggregate_page"` — `General`/mundane `ArmsArmor` → `advancedGear.html`, the *only* page the receipt cites for either; residual `MagicItems` → `wondrousItems.html`, the largest single named MagicItems bucket). Every URL used is real (taken directly from the SD-25 receipt's own citation list) — none is invented. Flagging this explicitly as a judgment call for operator review: a future cycle wanting per-item URL precision for the aggregate-tier ~296 records would need to redo/import SD-25's actual web-fetch research, not just re-run this generator.
  - **`fetched_at` for all `web_second_source` records uses the real commit date of the SD-25 sourcing cycle** (`2026-07-22T08:37:22-04:00`, commit `23fffa1` for equipment description; the spell-text cycle's own commit `a412d33` at `2026-07-22T09:19:53-04:00` was considered but the equipment-description commit date was used uniformly for simplicity since both are same-day/close-in-time real commits — this is a defensible proxy for "when this was sourced," not a fabricated date, since neither SD-25 receipt persisted a separate machine-readable fetch timestamp anywhere.
  - **`lst_corrected_ingest` covers 3 spell records, not the 2 headlined in `decisions.md §11.2`'s summary table.** `Fiery Body` and `Transmute Potion to Poison` gained real full text from the same-line `.MOD`-concatenation fix (matches the table's "2" exactly); `Fester (Mass)` is the *other* record on that same concatenated line, whose incorrectly-attributed full text was corrected back to its own real short description by the same fix — a real ingestion-defect correction in the same family, just not counted in the table's headline "recovered full text" framing. Included as `lst_corrected_ingest` for completeness/honesty (all three records' current values trace to the same documented same-line-concatenation defect fix), not a deviation from the schema's intent.
  - **Real LST citation lookup, not fabrication, for every `lst_token`/`lst_corrected_ingest` line number.** Per-class line numbers were transcribed from each class module's own doc comment (already hand-verified at SD-22 ingest time). Spell/equipment line numbers were **not** hand-typed — they were resolved at generation time by grepping the real corpus file (`~/workspace/repos/pcgen/data/pathfinder/paizo/roleplaying_game/advanced_players_guide/`) for the record's exact first-column name (falling back to a `.COPY=<name>` variant match, then a directory-wide scan across sibling `*.lst` files). This is citation lookup for an already-known-correct value, not value re-derivation (`decisions.md §11.3`'s actual prohibition) — confirmed empirically: the generator's `unresolved_citations` report was **empty** (0 of 641 records) on the real corpus, including the one record (`Formula Book`) whose category-file grep failed and was correctly recovered via the `.COPY=Formula Book` variant-line fallback (`apg_equip_general.lst:97`, `Spellbook.COPY=Formula Book`) — a genuinely more precise citation than my own initial guess (that it might live in `apg_templates.lst`) turned out to be.
  - **`sha256` computed via shelling out to the system `sha256sum`, not a new crate dependency.** No `sha2` crate exists in this workspace's `Cargo.toml`/`Cargo.lock` today; adding one for a generation-time-only concern seemed disproportionate. Mirrors `pcgen_runner.rs`'s established pattern of wrapping a real external tool.
