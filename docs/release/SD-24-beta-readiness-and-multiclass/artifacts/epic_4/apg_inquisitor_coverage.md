## Update (v0.6 alpha swarm, risks item 8, Inquisitor Judgment closure, third APG class-specific closure, 2026-07-25)

Inquisitor's own chassis-integration gate (`is_supported_inquisitor_single_class` in `pilot_compute.rs`) and its Justice judgment are now genuinely wired -- the third widening of `has_supported_class_chassis` to an APG class. Judgment combines the activation-gating pattern (Barbarian/Skald/Bloodrager Rage-shaped mechanics) with the choice-recognition pattern (Cleric's domain choice / Alchemist's mutagen-stat choice), the same combination Alchemist's Mutagen already proved -- not a new architecture. A new `choice:inquisitor_judgment` choice set (currently recognizing one selection, `judgment:justice`) combined with activation-gating (`class_ability_activations` entry `"judgment"`) grounds a real +1+floor(level/5) sacred-or-profane bonus to the integrated baseline melee attack bonus when actively, validly judging with Justice recognized. Justice was picked as the one canonical judgment type this closure grounds because it is the only one of the 8 whose bonus is a pure numeric attack-roll bonus requiring no new engine state (Destruction needs a damage-roll total this codebase doesn't compute anywhere; Healing/Resiliency/Resistance/Protection need fast-healing/damage-reduction/energy-resistance state that doesn't exist yet; Piercing/Purity/Smiting are opponent- or effect-type-dependent). The numeric bonus is identical whether the inquisitor's own alignment grants the Sacred or Profane variant, so no alignment branching was needed for the value itself. An active judgment with no recognized Justice choice (or a request naming a different, unbuilt judgment type) is a genuine posture violation and claim-blocks, mirroring Alchemist's own "active but no recognized stat choice" shape. Inquisitor's Domain was confirmed, directly against the corpus's own `KEY:Inquisitor ~ ...` list, to grant no separate domain power (only spell-list access) -- unlike Cleric's domain, so it needed no dedicated domain-power closure and is folded into the deferred spellcasting bucket instead. Inquisitor still does not reach `Computed` -- spellcasting, the other 7 judgment types, and every other named feature remain claim-blocked via the new `class_feature.apg.inquisitor.other_features_deferred.unsupported` diagnostic, which replaced the generic `class_feature.apg.inquisitor.unsupported` diagnostic for Inquisitor specifically. See `pilot_compute.rs`'s `inquisitor_dispatch_widening_safety_tests` module for the full test coverage.

## Update (v0.6 alpha swarm, risks item 8, Inquisitor Judgment deepening, 2026-07-26, task #3)

Re-verified the original closure's own "opponent/effect-dependent" exclusion of the other 7 judgment types directly against the raw corpus (`apg_abilities_class.lst`) rather than trusting the prior summary, and found it wrong for three of them: **Protection** (`KEY:Sacred Judgment ~ Protection`, `1+InqJudgeProtectionLVL/5` sacred/profane bonus to Armor Class) and **Purity** (`KEY:Sacred Judgment ~ Purity`, `1+InqJudgePurityLVL/5` sacred/profane bonus on all saving throws) are both flat, unconditional self-buffs with real live consumers already computed in this codebase (`baseline_armor_class` in `compute_combat_baseline`, `total_saves` in `compute_total_saves`) -- identical shape to Justice's own attack-roll bonus, not opponent-dependent at all. **Smiting** (`KEY:Judgment ~ Smiting`, `BONUS:VAR|InqJudgeSmitingLVL|InquisitorLVL`, no division/scaling) is a flat, level-independent boolean fact ("weapons count as magic for the purposes of bypassing damage reduction"), grounded as a standalone explanation record since no numeric total exists to layer it onto -- the same shape Brawler's Strike DR-bypass fact already established. All three now ground alongside Justice (`ground_or_block_inquisitor_judgment` widened from a single `if` check to an if/else chain over all 4 recognized selections, each with its own dedicated `active_inquisitor_<type>_judgment_bonus`/formula function), so `choice:inquisitor_judgment` now recognizes 4 of the 8 real judgment types. The remaining 5 (Destruction, Healing, Piercing, Resiliency, Resistance) genuinely still need engine state this codebase doesn't have: a damage-roll total, round-tick hit-point state, a concentration/caster-level-check total, a damage-reduction-received facet (distinct from Smiting's own DR-bypass-on-attack), and a chosen-energy-type mechanism plus an energy-resistance facet, respectively.

Also grounded **Stern Gaze** (`KEY:Inquisitor ~ Stern Gaze`, `max(1,InquisitorLVL/2)` morale bonus on Intimidate and Sense Motive checks) as a separate, top-level named feature -- unconditional the moment Inquisitor levels are present (a real level-1 class feature per `apg_classes.lst`'s own level-feature table, no choice or activation gate unlike Judgment). Only the Intimidate half lands in `compute_selected_skill_modifiers`; Sense Motive is not a skill this codebase computes anywhere, the same "ground only the computed half" discipline `feat_effects::skill_bonuses_from_feats` already applied to Persuasive's own Diplomacy half.

`named_features_wired` rises from 1 to 2 (Judgment slot + Stern Gaze slot -- Judgment's own 4 grounded sub-types stay one slot, per this repo's established "counts slots, not each slot's selectable sub-options" convention, the same reasoning that keeps Witch's ~20 individual hexes from inflating its own Hex-slot count). Inquisitor still does not reach `Computed` -- spellcasting, the 5 remaining judgment types, and every other named feature remain claim-blocked via the (updated) `class_feature.apg.inquisitor.other_features_deferred.unsupported` diagnostic. See `pilot_compute.rs`'s `inquisitor_dispatch_widening_safety_tests` module (8 new/updated tests) for the full test coverage.

## Update (task #18, 2026-07-26)

Monster Lore, Cunning Initiative, and Track are now also genuinely wired, correcting an over-strict "needs a live consumer" bar this closure's own Judgment deepening had applied. This codebase's own already-shipped precedent (Bard's own `class_chassis.bard.bardic_knowledge`, Slayer's own Track/Trapfinding, Barbarian's own Damage Reduction) already tolerates a genuinely-verified standalone flat fact with ZERO live consumer at all -- a consumer was never actually required, only a genuinely verified magnitude. Monster Lore (`KEY:Inquisitor ~ Monster Lore`, `BONUS:VAR|MonsterLoreBonus|WIS`) and Cunning Initiative (`KEY:Inquisitor ~ Cunning Initiative`, `BONUS:COMBAT|INITIATIVE|WIS`) both add the raw Wisdom modifier to Knowledge/Initiative checks respectively -- no Knowledge or Initiative total exists anywhere in this codebase, so both ground as standalone flat records. Track (`KEY:Inquisitor ~ Track`, `BONUS:VAR|TrackLVL|InquisitorLVL` plus the shared cross-class `TrackBonus|max(TrackLVL/2,1)` definition) is the identical real PF1 Track feature Ranger/Slayer share, confirmed byte-identical to Slayer's own `slayer_track_bonus` formula; kept as a separate Inquisitor-named copy (`inquisitor_track_bonus`) rather than reusing Slayer's function directly. All three are unconditional (no choice/activation gate, same shape as Stern Gaze) and never claim-block, grounded via a new `ground_inquisitor_flat_named_facts` function called alongside Judgment's own grounding. `named_features_wired` rises again, from 2 to 5. See `pilot_compute.rs`'s `inquisitor_dispatch_widening_safety_tests` module (3 new tests) for the full test coverage.
