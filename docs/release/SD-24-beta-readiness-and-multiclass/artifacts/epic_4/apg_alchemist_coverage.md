## Update (v0.6 alpha swarm, risks item 8, Alchemist Mutagen closure, second APG class-specific closure, 2026-07-25)

Alchemist's own chassis-integration gate (`is_supported_alchemist_single_class` in `pilot_compute.rs`) and Mutagen are now genuinely wired -- the second widening of `has_supported_class_chassis` to an APG class. Unlike every prior Rage-shaped closure (which affects a fixed set of stats), Mutagen genuinely requires a choice recognized via a new `choice:alchemist_mutagen_stat` choice set (Strength/Dexterity/Constitution), combined with activation-gating (`class_ability_activations` entry `"mutagen"`) for the first time this session -- the +4 alchemical bonus to the chosen physical score, the corresponding -2 mental-score penalty (Str->Int, Dex->Wis, Con->Cha, verified verbatim against the corpus DESC), and the +2 natural armor bonus are all genuinely applied to the integrated ability modifiers and Armor Class when a character is actively mutated with a recognized stat choice. An active mutagen with no recognized stat choice is a genuine posture violation and claim-blocks (mirrors Sorcerer's own "recognized bloodline but no bond choice given" shape), confirmed by direct edge-case review not to misclassify any real gameplay path. Confirmed via direct grep of `CharacterSheet.tsx` before scoping: this closure lands in the same headless-only reachability bucket as Sorcerer/Cleric/Druid's own choice-gated mechanics (no generic choice-picker exists in the creation/level-up UI). Alchemist still does not reach `Computed` -- spellcasting (extracts, genuinely cast via `SPELLSTAT:INT`) and every other named feature remain claim-blocked via the new `class_feature.apg.alchemist.spellcasting_deferred.unsupported` diagnostic, which replaced the generic `class_feature.apg.alchemist.unsupported` diagnostic for Alchemist specifically. See `pilot_compute.rs`'s `alchemist_dispatch_widening_safety_tests` module and `docs/release/v0.6/alchemist-mutagen-apg-second-class-scoping.md` for the full scoping record.

## Second update (v0.6 alpha swarm, risks item 8, Alchemist deepening, 2026-07-26, task #4)

A fresh re-scope after Investigator's own spellcasting closure (task #8) removed the original blocker (the shared Alchemist formula spell list didn't exist before; it does now) found Alchemist genuinely tractable, not "too big" as originally assessed. **Casting-shape correction**: the task note framed Alchemist's casting as "formula-based, different mechanic from Investigator's prepared shape" -- verified against the corpus and found imprecise: Alchemist is `HD:8 SPELLSTAT:INT MEMORIZE:YES SPELLBOOK:YES`, byte-identical to Investigator's own shape; extracts ARE the "formula" mechanic Investigator already grounds. **Bomb** (`KEY:Alchemist ~ Bomb`) is now fully wired: damage dice (`1 + (level-1)/2` d6 + INT bonus), save DC (`10 + level/2 + INT`), and uses-per-day (`level + INT`), all groundable as standalone facts since Bomb damage is a weapon-like magnitude against any target, not opponent-dependent the way Studied Combat/Strike are. **Verified the full 1-20 progression carefully, not just the base formula shape** (the same rigor the Sacred Weapon dice-count bug demanded): the corpus carries 10 conditional `-1` override branches on the damage-dice formula at odd levels 3-19, each gated behind an `Alchemist_CF_BombDamage<N>` flag that `DEFINE`s to `0` for the base class and is ONLY ever set by two specific Ultimate Magic archetype grants (Psychonaut, Reanimator) -- entirely out-of-scope splatbook content, so these branches are provably vacuous for this closure's scope, the same "provably vacuous precondition" shape Brawler's own light-armor check already established. A similar second `AlchemistBombTimes` contribution (`BonusBombCount/2`) is also provably 0: `BonusBombCount` only increments via a Gnome-specific Favored Class Bonus choice this codebase models nowhere. **Poison Resistance** (`KEY:Alchemist ~ Poison Resistance`) is now wired too -- re-derived independently against `AlchemistPoisonLVL`'s own tier tokens (not assumed from Investigator's identical-shaped feature): `+2` (level 2-4), `+4` (level 5-7), `+6` (level 8-9), full immunity at level 10+, confirmed identical to Investigator's own tiers. Kept as Alchemist's own separate functions/constants rather than calling Investigator's directly, the established parallel-copy discipline. **Prepared extract spellcasting** now genuinely validated too, reusing the shared `alchemist_spell_list` module (Alchemist IS the list's own namesake class, so this is direct reuse of the data, not a parallel copy) plus Alchemist's own extract-count table (confirmed byte-identical to Investigator's own via d20pfsrd.com's separate Alchemist page). `unmet_alchemist_extract_conditions`/`ground_alchemist_prepared_extracts` mirror Investigator's own shape exactly. Renamed `push_alchemist_spellcasting_deferred_diagnostic` to `push_alchemist_other_features_deferred_diagnostic` (`class_feature.apg.alchemist.other_features_deferred.unsupported` replacing `spellcasting_deferred`), with spellcasting's own dedicated `class_spell.apg.alchemist.prepared_extracts.unsupported` diagnostic. A valid extract posture now clears its own diagnostic; Alchemist still does not reach `Computed` overall (Discovery, Swift Alchemy, Swift Poisoning remain deferred). `named_features_wired` rises from 1 to 3 (Mutagen + Bomb + Poison Resistance -- spellcasting doesn't add a count, per the established convention). 19 new/updated dispatch-widening tests, both SD-24 APG audit tests updated and green.
