The now-retired `class_feature.acg.skald.spellcasting_deferred.unsupported` diagnostic is replaced by `class_feature.acg.skald.other_features_deferred.unsupported`, naming only Skald's remaining named features (Bardic Knowledge-analog, Iron Will, Rage Powers shared-list access, Spell Kenning, Versatile Performance, War Chant) -- **unlike Bard, Skald does NOT reach full `Computed` this closure**: Bard's own remaining features were already built in an earlier SD13-E5 cycle, but Skald's own equivalents remain completely unbuilt, confirmed directly rather than assumed by analogy. **Resolved (backend, 2026-07-26)**: known-spell-posture validation does NOT count as its own named-feature unit, per the same convention already established for every other partial caster this session (Oracle's own known-spell posture, Arcanist's Cantrips, Warpriest's Orisons, Inquisitor's spellcasting bucket) -- it "shares the general spellcasting mechanism," it is not an independently-implemented `KEY:Skald ~ ...` slot in its own right. Also checked the remaining named features directly against the real corpus for a next groundable slice: Bardic Knowledge/Lore Master need a Knowledge-skill total (doesn't exist); Rage Powers (shared-list access) and Spell Kenning are both real sub-selection subsystems (borrow-a-rage-power / borrow-a-spell-from-another-list); Versatile Performance needs Perform plus 5 other uncomputed skills as substitution targets; Well-Versed is a conditional bonus against specific incoming effect types this engine has no concept of; Dirge of Doom/Song of Marching/Song of Strength/Song of the Fallen all target allies or opponents, neither of which this engine models -- all of these remain genuinely subsystem-blocked. Damage Reduction was initially placed in that same bucket too (reasoned as needing "a generic DR-received facet"), but see the Third update below -- that reasoning was corrected.

## Third update (v0.6 alpha swarm, risks item 8, Skald Damage Reduction deepening, 2026-07-26, task #7)

The Second update's own conclusion that Damage Reduction needed an unbuilt "generic DR-received facet" was corrected after re-reading Barbarian's own precedent directly: `class_feature.barbarian.damage_reduction` (`pilot_compute.rs:17478`) is not shared plumbing at all -- it is a standalone, level-gated, flat-magnitude explanation record, "never applied to any incoming-damage total," the identical shape Smiting's own DR-bypass fact (Inquisitor, item 39) already established for this session. The absence of a shared/generic DR pillar does not block Skald from getting its own analogous standalone record; it only means no code gets reused, the same as every other per-class flat fact this segment. Verified the real corpus DESC directly: "At 9th level, a skald gains damage reduction... At 14th and 19th level this damage reduction rises by 1 point" -- DR 1/9th level, 2/14th, 3/19th, grounded via a new `ground_skald_damage_reduction`/`skald_damage_reduction_amount` pair mirroring Barbarian's own shape exactly, including the same "ground the absence, don't omit it" discipline below level 9. The ally-extension ("The skald grants this DR to all allies affected by his raging song") stays explicitly deferred -- this engine models no allies or ally-targeting mechanism at all -- so only the skald's own self-DR is grounded, the same "ground only the applicable half" discipline Persuasive's own Diplomacy half and Stern Gaze's own Intimidate half already established. `named_features_wired` rises from 1 to 2 (Inspired Rage + Damage Reduction, each a genuinely separate top-level `KEY:Skald ~ ...` record with independent grounding logic). Skald still does not reach `Computed` -- the other named features named above remain claim-blocked via the (updated) `other_features_deferred` diagnostic, which now also acknowledges Damage Reduction's self-only half as grounded in its own preamble while still naming the ally-extension as missing. See `pilot_compute.rs`'s `skald_dispatch_widening_safety_tests` module (3 new tests) for the full test coverage.
