# SD-35 Technical Design

The converter SD-35 builds, the live evaluator it builds, the status and gates it adds, the
PCGen code it removes from live paths, and the instruments it inherits. Every path was verified
present at `tranche/14` HEAD `5f6b18f4e3` on 2026-09-07 (`workflow-instruction.md §4`) and must
be re-verified at the `tranche/15` cut.

## 0. The boundary — PCGen on one side, the product on the other

**Operator ruling (`decisions.md §11`):** PCGen is a converter input and a test oracle. **Not one
line of it in live code.** At closure the live side contains no PCGen token syntax, no PCGen
formula evaluator, no `raw_tokens` reads, no PCGen description renderer.

| Side | Paths | May read PCGen? |
|---|---|---|
| **Converter / tools** — **kept for Starfinder** | `src/pcgen_import/**` (incl. `cache_gen/`, relocated there by AT-35-E6-002), `src/bin/gen_*`, `src/bin/enrich_*`, `src/bin/sheet_rule_convert.rs` (new), `src/bin/v06_work_inventory.rs`, `src/oracle_validation/**`, `scripts/oracle_harness/**`, `scripts/pcgen-oracle-pin.env`, `scripts/fetch-pcgen-oracle.sh`, `scripts/**`, `tests/**` | **yes** |
| **Live** | `src/rules_core/**` (except `cache_gen/` until relocated), `src/saved_character/**`, `src/campaign/**`, `src/homebrew_authoring/**`, `apps/desktop/**` | **no** |

**The tool side is kept, intact, for Starfinder** (`decisions.md §11`, what is kept). The exit
removes PCGen from the live side; it never deletes converter, parser, generator, or oracle code.

**The gate** (`scripts/pcgen_residue_gate.py --check`, AT-35-E1-005) greps the live side for
the PCGen surface — `raw_tokens`, `PcgenFormulaEvaluator`, `render_pcgen_desc`,
`bonus_stack_reader`, `pre_tokens`, and PCGen token syntax literals (`BONUS:`, `DEFINE:`, `PRE[A-Z]+:`,
`SAB:`, `DESC:`, `%CHOICE`, `%LIST`, `TYPE=`) — and prints a file count and a hit count. It
fails when either count is above the recorded baseline (monotonic: **the count only goes
down**), and at closure it fails on anything above zero. **At authoring, a coarse grep finds 78
files on the live side** (`content-unit-inventory.md §6`); the gate's first run records the
exact baseline.

## 1. The converter — `src/bin/sheet_rule_convert.rs` + `src/pcgen_import/sheet_rule/`

**Job.** Run once at ingest time, over every corpus record, and write our own rule record. It
is the only place the sheet rule's PCGen reading happens. It is a tool: it never ships in the
desktop binary and is never called at run time.

**Input.** One corpus record's token closure — base `.lst` row plus every `.MOD` row — the same
closure `wiring_class.rs` reads today.

**Output.** One `SheetRule` per record, in **our** schema, written to a derived data package
`data/sheet_rules/<book>/<kind>/<key>.json` (`GENERATED FILE` header; regenerated by the
converter; never hand-edited; the corpus under `data/corpus/` is not touched):

```rust
/// Our rule record. No PCGen in it — not a token, not a formula string, not a variable name.
pub struct SheetRule {
    pub id: String,            // "core_rulebook:race_trait_generic:racial_sla_charm_person"
    pub label: String,         // display name
    pub value: SheetValue,
    pub prose: String,         // the rule's words, already substituted (no %N, no %CHOICE markers)
    pub applies: Applies,      // what a character needs to hold this rule: class+level, race, feat, choice
    pub provenance: Provenance // book, page/source line, converter version — for the fine print and the oracle
}

pub enum SheetValue {
    Number(Expr),              // resolves to one integer for a character: Expr::Sum([Const(10), SpellLevel, AbilityMod(Cha)])
    Dice { dice: String, modifier: Option<Expr> },   // "1d8" + Const(2)  -> prints "1d8+2"
    Text,                      // nothing to compute; the prose IS the value
}

/// Our expression form. Closed vocabulary; every variant names a fact the live character has.
pub enum Expr {
    Const(i32),
    Level, ClassLevel(ClassId), CasterLevel(ClassId), SpellLevel,
    AbilityMod(Ability), AbilityScore(Ability), Size, HitDice, BaseAttack,
    Sum(Vec<Expr>), Mul(Box<Expr>, Box<Expr>), Div(Box<Expr>, Box<Expr>),   // Div floors
    Min(Box<Expr>, Box<Expr>), Max(Box<Expr>, Box<Expr>),
    Choice(ChoiceId),          // a term the player settles at pick time; unresolved -> the rule prints as words
}
```

**Conversion rule, stated once.** For each compute-bearing PCGen token in the closure, the
converter maps it to an `Expr` using a token-type table — `BONUS:VAR|X|TL` → `Level`,
`|CL=Wizard` → `CasterLevel(wizard)`, `|CHA` → `AbilityMod(Cha)`, `DAMAGE:1d8` → `Dice`, and
so on. A token type with no table row makes the record `Refused { token_type }` — **reported per
token type, never per unit** — and `token_coverage.py` counts it. Prose tokens (`DESC`,
`BENEFIT`, `ASPECT`, `SAB`, `SPROP`) are substituted at convert time into plain `prose`. A
record with no compute-bearing token is `Text`.

**What it reuses.** The PCGen formula parser inside `formula_interpreter.rs` (F1..F9) is the
right *parser*; the converter calls it to get an AST and then maps the AST to `Expr`. That file
**moves** to the converter side (AT-35-E6-001); it does not stay in `rules_core`. Same for
`bonus_stack_reader.rs` (typed-bonus stacking rules become a converter-side fold into `Expr`)
and `pre_tokens.rs` (prerequisites become `Applies`).

**Verification, with PCGen as the oracle.** The oracle harness (`scripts/oracle_harness/`) already
exports PCGen's computed totals for a character. AT-35-E2-005 and AT-35-E4-002 compare our
evaluated `Number` values against PCGen's for the same character. That is the whole legitimate
use of PCGen at run time: **in the test harness, checking that the rewrite is solid.**

## 2. The live evaluator — `src/rules_core/sheet_rule.rs`

**Job.** Given a `SheetRule` and a computed character, produce the line the player writes.

```rust
pub enum SheetLineValue { Resolved(i32), Dice(String), Words }
pub struct SheetLine { pub id: String, pub label: String, pub value: SheetLineValue, pub prose: String }

pub fn evaluate(rule: &SheetRule, character: &ComputedCharacter) -> SheetLine
```

`Expr` evaluation is a forty-line match over the enum. Every variant reads a field the
`compute_pilot_base_chassis` output already has (ability modifiers, level, class levels,
size). `Choice(_)` with no selection → `Words`. Dice folds its resolved modifier into the string.
**There is no parser here and no string evaluation.** Nothing in this module knows what a
`.lst` file is.

**Loading.** `data/sheet_rules/` is loaded by the same corpus loader path the desktop uses for
`data/corpus/` records, keyed by the same ids. The live side reads `SheetRule` JSON; it never
reads `raw_tokens`.

**Size.** Binds from the race table exactly as today. A rule whose `applies` names a size the
character is not renders `Words` or is omitted from the held set; the unit is `sheet-complete`
either way.

## 3. The status: `sheet-complete`

Added to `v06_work_inventory`'s `status_vocabulary` (AT-35-E2-003):

> `sheet-complete` — the record has a `SheetRule` in `data/sheet_rules/` with no refused token,
> the live evaluator renders it for a probe character that holds it, and the kind's on-screen
> test is green.

**Ladder position.** Above `engine-does-not-hold` / `ingested-magnitude`, below `grounded` /
`oracle-agree`. **Atlas.** DONE gains it; the DONE-evidence check requires
`sheet_rule_rendered:<form>`. **Consumers.** The last-added status (`oracle-unverifiable`) is the
grep census; every site learns `sheet-complete` in the same cycle.

## 4. The sheet section — `apps/desktop/src/characterHub/CharacterSheet.tsx`

One generic "Rules and features" section listing every held rule's `SheetLine`, grouped by
kind, on the existing sheet IPC payload. **19 frontend tests, one per kind** — SD-31 Decision 7
condition 3 satisfied once per kind. The `Not computed` lane keeps only records with no rule.

start of Epic 6 and again at its end; any drift is a defect in the exit, not a new bar.

## 9. Data regeneration

`data/sheet_rules/` is a derived package, regenerated whole by `sheet_rule_convert` once per
cycle that changes the converter. `data/corpus/**` is never hand-edited and — apart from
`beginner_box` (AT-35-E5-003) — never regenerated by this bundle. `sheet_rule_convert --check`
fails closed when the two disagree on record ids.
