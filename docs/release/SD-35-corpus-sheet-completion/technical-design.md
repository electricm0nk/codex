# SD-35 Technical Design

The converter SD-35 builds, the live evaluator it builds, the status and gates it adds, the
PCGen code it removes from live paths, and the instruments it inherits. Every path was verified
present at `tranche/14` HEAD `5f6b18f4e3` on 2026-09-07 (`workflow-instruction.md §4`) and must
be re-verified at the `tranche/15` cut.

## 0. The boundary — PCGen on one side, the product on the other

**Operator ruling (`decisions.md §11`):** PCGen is a converter input and a test oracle. **Not one
line of it in live code.** At closure the live side contains no PCGen token syntax, no PCGen
formula evaluator, no `raw_tokens` reads, no PCGen description renderer.

| Side | Paths | May read PCGen? |
|---|---|---|
| **Converter / tools** — **kept for Starfinder** | `src/pcgen_import/**` (incl. `cache_gen/`, relocated there by AT-35-E6-002), `src/bin/gen_*`, `src/bin/enrich_*`, `src/bin/sheet_rule_convert.rs` (new), `src/bin/v06_work_inventory.rs`, `src/oracle_validation/**`, `scripts/oracle_harness/**`, `scripts/pcgen-oracle-pin.env`, `scripts/fetch-pcgen-oracle.sh`, `scripts/**`, `tests/**` | **yes** |
| **Live** | `src/rules_core/**` (except `cache_gen/` until relocated), `src/saved_character/**`, `src/campaign/**`, `src/homebrew_authoring/**`, `apps/desktop/**` | **no** |

**The tool side is kept, intact, for Starfinder** (`decisions.md §11`, what is kept). The exit
removes PCGen from the live side; it never deletes converter, parser, generator, or oracle code.

**The gate** (`scripts/pcgen_residue_gate.py --check`, AT-35-E1-005) greps the live side for
the PCGen surface — `raw_tokens`, `PcgenFormulaEvaluator`, `render_pcgen_desc`,
`bonus_stack_reader`, `pre_tokens`, and PCGen token syntax literals (`BONUS:`, `DEFINE:`, `PRE[A-Z]+:`,
`SAB:`, `DESC:`, `%CHOICE`, `%LIST`, `TYPE=`) — and prints a file count and a hit count. It
fails when either count is above the recorded baseline (monotonic: **the count only goes
down**), and at closure it fails on anything above zero. **At authoring, a coarse grep finds 78
files on the live side** (`content-unit-inventory.md §6`); the gate's first run records the
exact baseline.

## 1. The converter — `src/bin/sheet_rule_convert.rs` + `src/pcgen_import/sheet_rule/`

**Job.** Run once at ingest time, over every corpus record, and write our own rule record. It
is the only place the sheet rule's PCGen reading happens. It is a tool: it never ships in the
desktop binary and is never called at run time. Its token-type table is
`artifacts/epic-2-sheet-rule/token-mapping/mapping-table.v1.json` (249 rows); the schema
decisions behind it are `token-mapping/SYNTHESIS.md §A`.

**Input.** One corpus record's token closure — base `.lst` row plus every `.MOD` row — read as
rows in PCGen order (`.COPY=` base → own row → `.MOD` rows in file order) through a corrected
mod index: `_pfs/` files are skipped by path, `.MOD` rows match on (file kind, CATEGORY,
KEY-else-name), and a base record is resolved corpus-wide (`SYNTHESIS.md §C4`). The closure is
read from the pinned PCGen tree (`scripts/pcgen-oracle-pin.env`), including the numbered class
level lines `ClassFeatureBlock.level_lines` and the `*_abilitycategories.lst` pool rows that
`data/corpus` never held (`§C10`, `§C11`).

**Output.** One `SheetRule` per record, in **our** schema, written to a derived data package
`data/sheet_rules/<book>/<kind>/<key>.json`, plus one contribution table per corpus variable
`data/sheet_rules/_vars/<VarId>.json` and a defect list `data/sheet_rules/_defects/*.json`
(`GENERATED FILE` header; regenerated by the converter; never hand-edited; the corpus under
`data/corpus/` is not touched):

```rust
/// Our rule record. No PCGen in it — not a token, not a formula string, not a variable name.
pub struct SheetRule {
    pub id: String,                 // "core_rulebook:race_trait_generic:racial_sla_charm_person"
    pub label: String,              // display name; codex-neutral when the name is PI (never from a redacted KEY)
    pub value: SheetValue,          // the line's principal value
    pub also: Vec<(ValueRole, SheetValue)>, // second/third numbers on one line: SPELLS uses+CL+DC (1,423 units), ASPECT:CheckCount uses (692 CW records)
    pub prose: Vec<ProseSegment>,   // the rule's words with typed slots, filled at evaluate time (5,149 CW records carry %N)
    pub applies: Applies,           // may THIS character hold it: class+level, race, feat, choice, facts
    pub target: Option<BonusTarget>,  // what sheet total this value feeds (AC, a skill, a save, a spell cell) — 11,000+ typed instances
    pub bonus_type: Option<BonusType>, // stacking type for the cross-rule fold ("Racial", "Dodge", Plain|Stack|Replace)
    pub print: bool,                // VISIBLE: YES/EXPORT/QUALIFY-when-held print; NO/DISPLAY are held silently (5,442 instances)
    pub pool: PoolId,               // from CATEGORY (Special Ability, FEAT, Archetype, Internal, ...)
    pub tags: Vec<Tag>,             // from TYPE (dot-segments; the (Ex)/(Su)/(Sp) label facet reads these)
    pub subject: Subject,           // Character (default) | Item — 1,252 PRETYPE gates on equipment
    pub repeatable: bool,           // MULT:YES
    pub granted_by: Vec<Grant>,     // who hands it out: ABILITY edges, class level lines, TEMPLATE, DOMAINS, CLASSES, choices
    pub offers: Option<Choice>,     // choice-bearing records (CHOOSE, ADD, SELECT, LANGBONUS, COMPANIONLIST)
    pub grants: Vec<Effect>,        // what holding it does to the fact set (AUTO, CSKILL, FACT, SERVESAS, QUALIFY, REMOVE)
    pub provenance: Provenance,     // book, closure rows (file:line), oracle pin, PI flags, converter version
}

pub enum ValueRole { Uses { period: String }, CasterLevel, SaveDc }

pub enum SheetValue {
    Number(Expr),                   // exact evaluation; ONE truncation toward zero at this boundary
    Dice { dice: String, modifier: Option<Expr>, size_steps: Option<Expr> }, // "1d8" + Const(2) -> "1d8+2"; size_steps = held DAMAGESIZE steps (586 instances)
    DiceBySize([String; 9]),        // UDAM list form indexed by Size ordinal, Fine..Colossal (5 units)
    Text,                           // nothing to compute; the prose IS the value
}

/// Words with typed holes. Text pieces are plain English from the record; no %N, no %CHOICE, no token.
pub struct ProseSegment {
    pub family: ProseFamily,        // Desc | Benefit | Special (SPROP/SAB) | Aspect(label from the 71-entry sub-key table) | WhenActive (TEMPDESC) | StatBlock(label)
    pub pieces: Vec<ProsePiece>,
    pub applies: Option<Applies>,   // a segment's own gate (~1,300 CW records carry PREVAR*/PRECLASS/!PREABILITY on a DESC or ASPECT segment)
    pub pick_last: bool,            // ASPECT: print only the LAST segment of this family whose gate passes (Aspect.java lastPassingAspect)
    pub suppress_when_all_zero: bool, // SPROP/SAB: omit the line when every slot evaluates to 0 (TextProperty.getParsedText)
}
pub enum ProsePiece {
    Text(String),
    Slot(Expr),                     // "DC %1" -> "DC 15"; truncated toward zero once per slot (Description.java:295 .intValue())
    ChoiceName(ChoiceId),           // %CHOICE / %LIST: the chosen option's name(s); unmade -> the choice lane's unmade words
    Dice { dice: String, modifier: Option<Expr> }, // "1d6+%2" stays dice
}

/// Our expression form. Closed vocabulary; every variant names a fact the live character has.
/// Evaluation is exact (rational); nothing here truncates — the SheetValue boundary does, once.
pub enum Expr {
    Const(i32),
    Level,                          // total character level (PCGen TL)
    ClassLevel(ClassId),
    CasterLevel(ClassRef),          // := ClassLevel(X) + held PCLEVEL contributions to X (SpellSupportForPCClass.java:165); Holder = the class the rule is held through (RANGE keywords, 665 units)
    SpellLevel,
    AbilityMod(Ability), AbilityScore(Ability),
    Size,                           // race-table size ordinal + held SIZEMOD contributions (175 instances)
    BaseSize,                       // race-table size before templates/evolutions (PREBASESIZE*, 41 units)
    SizeMod,                        // the size modifier to AC/attack for the current Size (2 units)
    HitDice,                        // RACIAL / monster-class hit dice; 0 for every PC race (PCHDTermEvaluator.java:35)
    BaseAttack,
    BaseSave(Save),                 // PRECHECKBASE (2 units)
    SkillRanks(SkillId), SkillTotal(SkillId), // skillinfo() 53 units; PRESKILL 143 units; SKILLRANK mirroring
    HeldCount { pool: PoolId, filter: HeldFilter }, // count("ABILITIES", ...) 45 units + 21 PREVARLT
    ChallengeRating,                // SR:11+CR on monsters (19 units)
    Speed(MoveMode),                // MOVECLONE / MOVEMULT read a mode's speed (25 units)
    HighestSpellLevel(SpellKind),   // PRESPELLTYPE, PRECLASS SPELLCASTER (16 units)
    MasterLevel,                    // companion records: the master's level (209 gates)
    MasterVar(VarId),               // mastervar("X") (13 units)
    Var(VarId),                     // a corpus variable: folded over the HELD contributions in data/sheet_rules/_vars/<VarId>.json (6,699 units)
    Sum(Vec<Expr>), Mul(Box<Expr>, Box<Expr>), Div(Box<Expr>, Box<Expr>), // Div is EXACT (452 units diverge under per-step floor)
    Min(Box<Expr>, Box<Expr>), Max(Box<Expr>, Box<Expr>),
    Floor(Box<Expr>), Ceil(Box<Expr>), // explicit floor() 433 units, ceil() 41 units
    Choice(ChoiceId),               // a term the player settles at pick time; unresolved -> the rule prints as words
}
pub enum ClassRef { Class(ClassId), Holder }

/// An opaque converter-minted id: "v" + 16 hex of SHA-256 over the upper-cased PCGen name.
/// The name -> id map is written tool-side only (scripts/oracle_harness/var_names.json, generated),
/// so nothing PCGen-shaped reaches data/sheet_rules/ or the live side.
pub struct VarId(String);

/// data/sheet_rules/_vars/<VarId>.json — every contribution to one variable, corpus-wide.
pub struct VarTable {
    pub var: VarId,
    pub declared_by: Vec<RuleId>,   // rules whose closure DEFINEs the name; no held declarer -> the value is 0 (PlayerCharacter.java:2124-2136)
    pub contributions: Vec<VarContribution>,
}
pub struct VarContribution { pub rule_id: RuleId, pub expr: Expr, pub bonus_type: Option<BonusType>, pub when: Applies }
pub struct BonusType { pub name: String, pub mode: StackMode } // name is a game-rule word ("Racial", "Base"), never a token
pub enum StackMode { Plain, Stack, Replace }
/// Game-rule constant (Pathfinder): typed bonuses of these types stack; every other same-type pair takes the max.
pub const STACKING_TYPES: [&str; 6] = ["Defense", "Dodge", "Circumstance", "Racial", "NotRanged", "NotFlatFooted"];

pub enum BonusTarget { Ability(Ability), Skill(SkillId), Save(Save), Ac, Attack, Damage(WeaponRef), Hp, Initiative, Cmb, Cmd, Speed(MoveMode), Vision(Tag), Dr, SpellDc(Scope), CasterLevel(Scope), SpellCell { class: ClassId, level: u8 }, Pool(PoolId), Other(String) }

/// The gate. Two-valued (Include / Exclude) plus Situational, which includes and prints its condition on the line.
pub enum Applies {
    Always, Never,
    All(Vec<Applies>),
    AtLeast { n: u8, of: Vec<Applies> },              // PREMULT:n and every PRE<x>:n,... count form
    Not(Box<Applies>),                                // !PRE<x>; archetype replacement = Not(Holds{setter})
    Compare { lhs: Expr, op: Cmp, rhs: Expr },        // PRESTAT, PRESKILL, PRETOTALAB, PRELEVEL, PREHD, PRESIZE*, PREBASESIZE*, PRECLASS, every resolved PREVAR*
    Holds { what: Holdable, count: u8 },              // PREABILITY, PRERACE, PREFACT, PRETEMPLATE, PREALIGN, PREDEITY*, PREDOMAIN, PRECSKILL, PREWEAPONPROF, PRESPELL*, PREMOVE, PREVISION, PRELANG, flag-shaped PREVAR*
    Chosen { choice: ChoiceId, option: Option<OptionId> }, // %CHOICE / %LIST-bound grants; parameterised feats (base id + option)
    ItemHas { tags: Vec<Tag>, n: u8 },                // PRETYPE (subject = Item)
    Situational { text: String },                     // Include; the condition prints on the line: PRETEXT 139, PREEQUIP/PREARMORTYPE/PREDR/PREHANDS/PREREACH, TEMPBONUS 418, redacted gates
}
pub enum Cmp { Eq, Ne, Lt, Lte, Gt, Gte }
pub enum Holdable {
    Rule(RuleId), RuleTag { pool: PoolId, tag: Tag }, Template(RuleId), Spell(RuleId),
    Race(RaceId), RaceType(Tag), RaceSubtype(Tag),
    Alignment(AlignSet), AlignmentMatchesDeity, Deity(DeityRef), DeityInPantheon(String), DeityGrantsDomain(RuleId), DeityAlignment(AlignSet),
    ClassSkill(SkillId), Proficiency(ProfRef), Language(LangRef), Movement { mode: MoveMode, min: u16 }, Vision(Tag),
    ClassTag(Tag), Gender(Tag), AgeCategory(Tag),
}
pub struct Grant  { pub by: Granter, pub when: Applies }   // Granter = Rule(id) | Class { id, at_level } | Race(id) | Deity(id) | Choice(ChoiceId)
pub struct Choice { pub id: ChoiceId, pub count: Expr, pub from: OptionSet }
pub enum OptionSet { Rules { pool: PoolId, tags: Vec<Tag>, requires: Applies }, Skills(..), Weapons(..), Spells { class: ClassId, levels: (u8, u8) }, Languages(..), Templates(..), Classes(..), Races(..), FreeText, Number { min: Expr, max: Expr } }
pub enum Effect { FactGrant(Fact), FactRevoke(Fact), CountsAs(CountsAs), Waives(RuleId), Revokes(RuleId), FactDeclare { name: String, value: String } }
pub enum CountsAs { Rule(RuleId), Class(ClassId), Race(RaceId) }
```

**Conversion rule, stated once.** For each token in the closure, the converter looks up its
row in `mapping-table.v1.json` by token type (and BONUS sub-target) and applies that row's
rule — `BONUS:VAR|X|TL` → a `VarContribution{expr: Level}` on `X`'s table, `|CL=Wizard` →
`ClassLevel(wizard)`, `|CHA` → `AbilityMod(Cha)`, `DAMAGE:1d8` → `Dice`, `DESC:DC %1|X` →
`ProseSegment{[Text("DC "), Slot(Var(x))]}`, `PREVARGTEQ:X,8` → `Compare{Var(x), Gte, Const(8)}`,
and so on. A token type with no row makes the record `Refused { token_type }` — **reported per
token type or token shape, never per unit** — and `token_coverage.py` counts it. A record with
no compute-bearing token is `Text`. Names DEFINEd nowhere split three ways (`§C1`); the mod
index and closure follow `§C4`; class level grants come from the class `.MOD` closure plus the
numbered level lines (`§C10`).

**What it reuses.** The PCGen formula parser inside `formula_interpreter.rs` (F1..F9) is the
right *parser*; the converter calls it to get an AST and maps the AST to `Expr` by the FORMULA
rows: `/` → exact `Div`, `floor()`/`ceil()` → `Floor`/`Ceil`, `if()` and comparisons → the exact
`Min`/`Max` encoding (`§C17`), a corpus variable → `Var`. That file **moves** to the converter
side (AT-35-E6-001); it does not stay in `rules_core`. Same for `bonus_stack_reader.rs` (its
producer-chain walk becomes the `_vars/` table emitter; the typed fold moves to the live
evaluator as a forty-line function over `BonusType`), `pre_tokens.rs` (prerequisites become
`Applies`, two-valued), `wiring_class.rs` (`build_mod_index` / `token_closure_rows`, corrected
per `§C4`), and `render_pcgen_desc`'s tokenizer (segments and gates; the argument rule is
replaced by `§C5`). The variable index is one converter component with one owner
(case-insensitive, corpus + pinned data), used by the BONUS, FORMULA, PRE and prose rows alike.

**Verification, with PCGen as the oracle.** The oracle harness (`scripts/oracle_harness/`) already
exports PCGen's computed totals for a character. AT-35-E2-005 and AT-35-E4-002 compare our
evaluated `Number` values against PCGen's for the same character, and every DESC slot value
against `SA.n.DESC` (PCGen's own substituted words). The named PCGen-divergence classes —
the 68 Div-under-Mul formulas, bare `CL` on 24 non-class records, `%%N`, `%CHOICE` in ASPECT,
multi-source VISION — are recorded in `artifacts/epic-6-pcgen-exit/` so parity does not chase
them one by one. That is the whole legitimate use of PCGen at run time: **in the test harness,
checking that the rewrite is solid.**

## 2. The live evaluator — `src/rules_core/sheet_rule.rs`

**Job.** Given a `SheetRule`, the character's held set, the `_vars/` tables, and a computed
character, produce the line the player writes.

```rust
pub enum SheetLineValue { Resolved(i32), Dice(String), Words }
pub struct SheetLine {
    pub id: String, pub label: String,
    pub value: SheetLineValue,
    pub also: Vec<(String, SheetLineValue)>,   // "6/day", "CL 5", "DC 15"
    pub prose: String,                         // slots filled; segments joined; nothing unsubstituted
    pub condition: Option<String>,             // Situational text: "when jumping", "while raging"
}

pub fn evaluate(rule: &SheetRule, held: &HeldSet, vars: &VarTables, character: &ComputedCharacter) -> SheetLine
```

**`Expr` evaluation** is a match over the enum returning an exact rational (`i64` numerator and
denominator; division by zero yields 0). Every leaf reads a field the `compute_pilot_base_chassis`
output already has (ability modifiers and scores, level, class levels, caster levels including
held PCLEVEL contributions, size and base size, racial hit dice, BAB, base saves, skill ranks and
totals, speeds, CR, highest spell level, the companion master's level) or a held count.
`Floor`/`Ceil` apply to the exact value. **Truncation toward zero happens exactly once**: when a
`SheetValue::Number` becomes `Resolved(i32)`, when a `Dice.modifier` or `size_steps` is folded,
and when a `ProsePiece::Slot` is printed. No intermediate step truncates. `Choice(_)` with no
selection → the line is `Words`.

**`Var` contribution fold.** `Var(id)`: if no HELD rule is in `vars[id].declared_by`, the value
is 0. Otherwise take every `contribution` whose `rule_id` is held and whose `when` evaluates
Include, evaluate its `expr`, and fold by `bonus_type`: contributions with no type, with
`StackMode::Stack`, with a negative value, or whose type is in `STACKING_TYPES` are summed;
the remaining contributions of one type take the max; for a type that also has `Replace`
contributions the result is `max(plain + stack, replace)`. The same fold, keyed by
`SheetRule.target` and `bonus_type` across every held rule, produces the sheet totals
(AC, skills, saves, spell cells), so two racial +2s to the same skill print as +2.

**Held set.** A fixpoint: start from the character's race, class levels, templates and
choices; add every rule some held rule grants (`granted_by`) whose `when` and `applies`
evaluate Include; apply `Effect`s (facts, counts-as, waivers, revokes); repeat until nothing
changes. `print == false` rules stay in the set and off the sheet.

**`Applies` evaluation** is two-valued. `Compare`, `Holds`, `Chosen`, `ItemHas` read facts;
`AtLeast` counts Includes; `Not` flips. A leaf over a fact the character record does not yet
carry (alignment, deity, gender, age category, base size, spells known, companion master)
evaluates Exclude — a grant is never silently held — and the missing fact is a named blocker,
not a third truth value. `Situational{text}` evaluates Include and sets `SheetLine.condition`;
the value still computes and the line reads "+8 Acrobatics, when jumping".

**Slot filling.** For each `ProseSegment` whose `applies` is Include (a segment with none is
Include): within a `pick_last` family only the last such segment prints; a segment with
`suppress_when_all_zero` prints only if some `Slot` is non-zero. Pieces render in order:
`Text` verbatim, `Slot` as the truncated integer, `ChoiceName` as the chosen option's name(s)
(sorted; two join with " and ", more with ", ") or the choice lane's unmade words, `Dice` with
its modifier folded in. Families join in the order Desc, Benefit, Special, Aspect lines
(`<Label>: <text>`), StatBlock lines, WhenActive (`When active: <text>`).

**Dice.** `Dice` folds its resolved `modifier` into the string ("1d8+2") and steps the die by
the resolved `size_steps`; `DiceBySize` indexes by the character's `Size` ordinal.

**There is no parser here and no string evaluation.** Nothing in this module knows what a
`.lst` file is, what a PCGen variable was called, or what `%1` meant.

**Loading.** `data/sheet_rules/` (rules and `_vars/`) is loaded by the same corpus loader path
the desktop uses for `data/corpus/` records, keyed by the same ids. The live side reads
`SheetRule` and `VarTable` JSON; it never reads `raw_tokens`.

**Size.** `Size` is the race-table ordinal plus held SIZEMOD contributions; `BaseSize` is the
race-table ordinal alone. A rule whose `applies` names a size the character is not renders
Exclude and is omitted from the held set; the unit is `sheet-complete` either way.

## 3. The status: `sheet-complete`

> `sheet-complete` — the record has a `SheetRule` in `data/sheet_rules/` with no refused token,

grep census; every site learns `sheet-complete` in the same cycle.
