## Blocker (status blocked-escalated)

1. **The live record carries no tags and no tokens.** `CorpusEquipmentRecord` is deserialized from
   `data/corpus/<book>/_settled/equipment.json` (`src/rules_core/corpus_loader.rs:100–115`), written at authoring time by
   `crates/codex-ingest/src/bin/gen_settled_corpus.rs` through `ir_converter::equipment_record_to_corpus`
   (`crates/codex-ingest/src/pcgen_import/ir_converter.rs:492`). The settled Backpack record
   (`_settled/equipment.json` key `general/backpack.json`) has weight, cost and the weapon/armour fields only.
2. **Capacity has no live source inside the fence.** `data/sheet_rules` holds no `CONTAINS` (decisions §7); the only
   source is the corpus record's `raw_tokens`, and reading `raw_tokens` in live code is a `pcgen-residue-gate` hit
   (`scripts/pcgen_residue_gate.py:211`) and contrary to `decisions.md §17`. The capacity must be settled by the
   converter and written into the `_settled` bundles — files outside E1.1's FILES YOU OWN, and the converter file is
   E1.9's (lane `convert`, running in parallel in `.worktrees/sd41-convert`). `decisions.md §19`: no edit outside
   FILES YOU OWN before the owning epic's merge check is complete.
3. **`gen_settled_corpus` also writes `apps/desktop/src-tauri/resources/corpus_fixtures/_settled/equipment.json`**
   (its doc comment, lines 27–33), and the desktop fixture sources hold Container-tagged weapons
   (`grep -l 'CONTAINS\|Container' -r apps/desktop/src-tauri/fixtures_src/equipment/` → 10 files, e.g.
   `equip_pistol_dragon.json`, `equip_longbow_base.json`). Any new settled field that is non-default on those weapons
   moves an `apps/` file, which Phase 1 forbids. (Avoidable: see the proposed change, point (b).)
4. **SD-a's premise is false.** It says ammunition holders have *no* `Container` tag; Pistol and Powder Horn both have it
   (sheet rules `ultimate_equipment/equipment/pistol.json` tags `[Weapon, …, Container, Projectile, Firearm, …]`;
   `powder_horn.json` tags `[Goods, FirearmGear, Powder Horn, Container]`). The tag alone makes Pistol a container,
   contradicting the criterion's "Pistol → not a container". A rule is needed (default proposed below).

## Proposed change (ready to apply once R1/R2 are granted)

(a) `equipment_record.rs`: `pub enum ContainerCapacity { Pounds(f64), Unlimited, #[default] Unstated }` (serde);
fields `#[serde(default, skip_serializing_if = …)] pub container: bool` and `pub container_capacity: ContainerCapacity`;
`is_container()` / `capacity()` read them. (b) Converter: `container = TYPE has Container && DAMAGE absent`;
`container_capacity` from `CONTAINS`'s first `|` field (`UNLIM…` → Unlimited, `*…` → Unstated, a number → Pounds,
absent → Unstated), settled only when `container` — so every weapon serializes unchanged and the `apps/` fixture
bundle does not move (`gen_settled_corpus -- --check` on the desktop bundle stays clean). (c) Tests over the settled
bundles with corrected populations (below).
