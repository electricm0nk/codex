# Adjacent-Lane Boundary and Breadth-Claim Contract

## Objective
Define the seam between SD-13 breadth truth and the adjacent lanes so later work cannot smuggle tester, distribution, or persistence scope into a roster packet by implication.

## Boundary table
| Lane | What it owns | What SD-13 may feed into it | What it must not infer automatically from SD-13 |
|---|---|---|---|
| SD-11 | tester-facing workbench structure, issue flows, evidence packaging, support wording | support-state rows, debt rows, breadth-claim composition rules | UI presence or nicer wording as proof that a class/race is supported |
| SD-12 | branch/channel/distribution/update truth, platform tiers, publication surfaces | roster-support metadata that shipped builds may display or carry | shipping a build as proof that roster semantics or level-10 progression are complete |
| SD-14 | saved-state continuity, upgrade survival, migration, persistence diagnostics | roster identity and support-state metadata when save compatibility later depends on breadth | save/load or migration success as proof that a class/race is supported |
| GE-06 | current accepted Human Fighter pilot proof ceiling | the hard floor from which SD-13 must begin truthfully | pilot success as broad core-roster proof |
| GE-10 | truthful current-state and onboarding narrative | plain-language statements about the current breadth ceiling | onboarding or demo polish as evidence of class/race support |

## Breadth-claim rule for downstream consumers
Any downstream consumer of SD-13 truth must:
1. cite the relevant SD-13 matrix rows
2. preserve the support state and visible debt
3. preserve the evidence tier when claim strength matters
4. refuse to upgrade claim language merely because the consumer lane succeeded at its own job

## Examples of invalid inference
- “The Linux tester build ships, therefore core roster support is ready.”
- “The tester workbench shows Bard in a list, therefore Bard is supported.”
- “The save file reopens, therefore the underlying class/race semantics are complete.”

## Examples of valid use
- “The tester workbench may display Fighter as partial because SD-13 class rows say Fighter is partial beyond the pilot ceiling.”
- “A shipped build may carry a support matrix snapshot while still warning that several classes remain blocked or unverified.”
- “A future persistence lane may mark a saved character as depending on a partial breadth row without promoting that row to supported.”
