## Not closed at attempt 1 — escalated, CLEARED at attempt 2 (`decisions.md §20`; kept as the record)

It is **not** closed for two feeds, both owned by `src/rules_core/pilot_compute/sf_loadout.rs`, which E5's file row forbids (`workflow-instruction.md §3`: E5 "**Never** `pilot_compute/**`"; E4.5 owns the file):

1. **Installed upgrades' price and bulk → credits spent / bulk.** `sf_loadout::item` refuses any record whose kind is not `equipment` (`sf_loadout.item_not_equipment`) and `SfLoadout` has no field for applied modifiers, so an installed upgrade prints its `Price:` and `Bulk:` (this card's converter change) but adds to neither total. Count: 222 priced equipment modifiers (`E5.3_delta.py`), 108 with a bulk row.
2. **Augmentations → credits spent.** All 144 augmentation principals state no bulk (the oracle's augmentation rows carry `QUALITY:ItemLevel` only; the SRD augmentation page states none either, `E5.3-srd-fetch-log.txt`), and `sf_loadout::bulk` refuses an item with no bulk (`sf_loadout.item_bulk`): a character carrying any augmentation computes no sheet at all. The augmentation print path is built and tested at `sheet_lines` level, but no saved character can reach it until the loadout accepts the item.

Prepared change (NOT applied, not compiled): `E5.3-proposed-sf_loadout.patch` adds `SfLoadout::applied` and accepts `equipment_modifier` records (price + bulk when stated; a fusion with neither adds nothing). The augmentation bulk rule needs a ruling (below) before it can be written.
