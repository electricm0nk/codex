## Does not cover

- **The compiled module is still compiled and still read in four ways.** (1) 444 items are re-exported by name: 178 types whose `impl` methods stay compiled, 186 pure functions (formulas over their arguments), 78 scalar consts, 2 inline modules. They are code, not table rows. E4a.4's "no `.rs` left" has to place every one of them; this card did not. Detection predicate for "a function that reads a table": a token of its body names a registered table, a view, or a function already so flagged (`gen_catalog.py`, run to a fixed point over all 250 files) — a read through a path that predicate cannot see (a trait object, a re-exported alias, a macro-generated call) would be a function this card re-exports unreplaced. The `impl` blocks were scanned with the same predicate: 0 read a table (2 hits, `impl MonsterBook` / `impl CompanionBook`, are field names that equal function names). (2) The package writer, E4a.1's round-trip tests and this card's equivalence tests read the compiled tables on purpose (they are the oracle until E4a.4). (3) Two enum types are registered package tables and re-exported with compiled methods: `UnchainedRogueFeature`, `UnchainedSummonerFeature` (their per-variant `key`/`name`/`declaring_line`/`min_level` answer from `match` arms). (4) `monster_subset_01..09` (Bestiary 1's 46 constructors) are not mirrored; they are reachable only through the compiled `monster_resolve`, which the catalog replaces by the package's 46 rows.
- **Provenance text still names the compiled module.** 44 literal sites in 17 files (14 `concat!` splits, 30 interpolations; the two `grep … | awk 'END{print NR}'` commands in the "What shipped" row) print "rules_tables::…" so the render stays byte-identical. Renaming the citation is a PF re-baseline: operator ruling, SD-i. The acceptance literal counts source text, not output bytes.
- **The acceptance counts the literal `rules_tables::`.** The catalog's own files name the compiled module through `use crate::rules_core::rules_tables as rt;` (the same way `rules_data_package.rs` does), so they do not match; `grep -rlE 'rules_core::rules_tables' src crates apps/desktop/src-tauri tests --include='*.rs' | awk '!/src\/rules_core\/rules_tables\//' | awk 'END{print NR}'` counts the files that still name it at all.
- **Equivalence is proven over the rows and the domains the tests walk.** Tables and views: every row (JSON equality). Lookups: the 7 override families over their whole domain; the 104 copied items that are not views (readers, their private helpers, 2 inline modules) are verbatim copies of compiled source reading rows proven equal, and are exercised by the importers' own suites (root/ingest/desktop above) and the PF hash pair, not one by one.
- **Packaged-app proof is a child-process probe plus a wiring test, not a packaged build.** No installer was produced and the app was not launched (no browser on this box); the first tester publish after the operator merges is the first packaged build that reads the package. The bundle carries 13 MB more JSON (E4a.1) and the NSIS-only Windows build (PR #394) was not measured with it.
- **Load cost.** A table is parsed on first use; the suite's wall time rose from 364 s to 404 s for the lib tests (`E4a.1_logs/root-full.log` vs `E4a.2_logs/root-full.log`, this card's 13 tests included); no per-call timing was taken for the desktop.
- **`.lst` text:** the catalog's copied source carries 7 `.lst` lines (`grep -rcF '.lst' src/rules_core/rules_catalog | awk -F: '{s+=$2} END{print s+0}'`), which E4a.3's report over `src/rules_core` outside the compiled module will include.
