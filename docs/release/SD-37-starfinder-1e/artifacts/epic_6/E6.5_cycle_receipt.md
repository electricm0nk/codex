## What the level-up is

The Starfinder sheet's **Level up** opens `StarfinderLevelUpDialog`. Every list, cap and number in it is `preview_starfinder_level_up`'s answer for the current choices:

| Asked | Source | Saved as |
|---|---|---|
| class | held classes first (advance), then every other class record with its key-ability options (`sf_creation::class_options`) | `class_levels` +1, or a new class at 1 with its key-ability choice |
| ability increase (character level 5/10/15/20) | `sf_abilities::INCREASE_LEVELS`, `SCORES_PER_INCREASE`; each score's step `sf_abilities::increase_term` | final `ability_scores` raised |
| skill ranks this level | the package's base skills; ranks in one skill ≤ the new character level (SRD Acquiring Skills, ID=77) | `skill_allocations` added |
| picks the new level opens | `sf_creation::discover` on the held set at the new level vs now (new slot, or a slot whose count rose) | rule choices |
| what the level changes | `sf_adapter::compute_sheet` now and at the new level; every `sf.*` row whose value differs, both values | — (printed) |

Printed, never computed (`decisions.md §5`): the class record's own stat-block rows (`Skill ranks per level: 4`, no hit die), the odd-level feat line (SRD Table 2-4, ID=56), and "chosen on the sheet" picks the level owes (feat pools, languages). "Accept level-up" calls `level_up_starfinder_character`, which recomputes the preview, refuses (saves nothing) on any blocking problem, requires `compute_sheet` to succeed, then saves the next revision. The sheet then re-reads the character (`load_saved_character`) and prints `Leveled up: <level line>`.
