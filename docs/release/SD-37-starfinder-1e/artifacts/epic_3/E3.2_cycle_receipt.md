- **What was built.**
  - `sheet_rule::formula_system` reads, through E3.1's `resolve_book_includes` (so only the 8 registered books, never an excluded one): the `VARIABLE:` files (`GLOBAL:`/`LOCAL:`/`CHANNEL:`, `FORMAT=` defaulting to `NUMBER`), the `DATACONTROL:` files' `FUNCTION:` and `DYNAMICSCOPE:` rows, the `DYNAMIC:` objects and the `DATATABLE:` tables (row width and `NUMBER` cells checked); then every `MODIFY:`/`MODIFYOTHER:` tab field, split as `ModifyLst`/`ModifyOtherLst` split it, checked as PCGen's loader checks it — variable declared and legal in the carrying object's scope (scopes from each PCGen object's `getLocalScopeName()`, child scope draws from parent), case-insensitive names (`VariableManager`'s `CaseInsensitiveMap`), modifier legal for the format (`plugin/modifier/<format>/`), `MODIFYOTHER` scope a declared dynamic scope and grouping a declared object of it, value parsed (formula grammar; ordered-pair literal for `ORDEREDPAIR`) with every identifier a legal variable, every function known (PCGen-Formula built-ins, PCGen plugin functions, the data's `FUNCTION:` rows), `input("x")` a declared `CHANNEL:`, `lookup("t",…)` a declared `DATATABLE`; then the variable's sheet role (`VARIABLE_ROLES`: compute vs print, the paper-sheet rule). Pass → `Mapped {variable, format, role, sheet, value}`; fail → `Refused {reason}` naming the failed check. Nothing is evaluated and no rule file is written.
