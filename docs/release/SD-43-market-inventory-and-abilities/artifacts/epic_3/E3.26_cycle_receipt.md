- **Rulings and defaults applied:** (1) The target rides in the option id (`<pool>:<record>|<value>`, `TARGET_SEPARATOR` = the save line's own `|`), because the Class Features `onAdd` lives in the hub `CharacterSheet.tsx` and drops the choice; a `|` or line break in a value is refused. Alternative not taken: a `target` field on `AbilitySelectionRequest` (needs a hub edit). (2) A parameter choice is its own pool `<record slug>_choice` sized by the offer's count, its one option the record — so MULT picks with different values each charge one, and a value taken twice is refused (`already holds`). Alternative not taken: a target on the pick that took the record from its own pool (cannot serve a record held through its class with no pick). (3) Values listed only where the corpus names members: skills / languages / classes / races (all of the kind for an empty list), equipment records a weapon list names, spells of the class list and levels, a tagged ability list; a weapon class, `QUALIFIED`, a spellcaster, an untagged base category, schools, items and free text list none and the player writes the value in (the `words` say what). Alternative not taken: a hand-kept school list (no hand-kept tables). (4) A record whose `CHOOSE:` was screened as product identity (5 Hermean Blood records) keeps `ClassSkillChosen(<own id>)`, so its choice is a skill. (5) A weapon offer on a record that also sizes a pool (Kensai / Geisha Weapon Proficiency) is the record's own parameter — a pool's members are records, never weapons; Races / Rules offers on a pool grant stay the pool's members. (6) A creation choice already recorded under the record's id (the Expert's ten canonical class skills) answers the parameter: no pool. (7) The facts record the target under the record's choice id (`record_pick`), the reader its `Chosen` grants already use — so a target is not decoration.
