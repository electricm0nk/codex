- **Rulings and defaults applied:** `technical-design.md §3.2` (pools from the rules held, never a per-class table; picks in
  `ability_selections`). Defaults (§30, no operator question): (1) the level a pick is charged to is the **character** level its grant opened
  at (single-class = class level; a multiclass reads character levels, as `AbilitySelection.level` is documented); alternative not taken:
  per-class level, which needs the owning class of every grant line. (2) A pick names `<pool>:<record id>`; two printings of one name are
  offered once (first record id). (3) Options carry the record's own gate verdicts (the converted-gate evaluator Traits use), so
  "qualified" is not claimed blindly; E3.5 owns the pool-member prerequisite evaluator and refusal wording. (4) A companion-status / trick
  pool the character picks for its companion is a Class Features pool (subject Character); a pool on an item is not.
