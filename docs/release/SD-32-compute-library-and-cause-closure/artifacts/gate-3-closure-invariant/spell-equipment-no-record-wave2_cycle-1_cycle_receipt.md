**Confirmed real cause for these two:** the base item ("Dust Knuckles") is a genuine content row

`advanced_class_guide/_pfs/pfs_acg_equip.lst:6`, carries `Dust Knuckles.FORGET` — a Pathfinder
Society legality-retraction directive, not a content declaration.
`gen_equipment_gap_tables.rs`/`gen_cache_equipment_gap` correctly exclude `.FORGET` rows as
non-content (the equipment_modifier receipt's own run already reported "5 record(s) excluded as
non-content (.FORGET / disabled #-line)" for a different population). The defect is one layer up,
in whatever enumerates `docs/work-inventory.json`'s units: it appears to mint a **separate** unit
id for the `.FORGET` directive (`..._forget`) as though it were its own distinct object, rather
than recognizing it as a retraction annotation on the SAME already-real "Dust Knuckles" item. That
enumeration path is `v06_work_inventory.rs` (15,821 lines, per `decisions.md §17`'s own
measurement) — outside this cycle's granted file scope (`hand_authored_equipment.rs`/
`gen_equipment_gap_tables.rs`, not the census/inventory binary itself) and not attempted here.

**Only 2 of 170 carry a `_forget` suffix** (`grep -c '_forget$'` over the 170 ids) — this is a
real, confirmed cause but a small one, not the dominant shape. The remaining 168 need their own
trace; not attempted this cycle (budget spent on the `spell` widening, which was the larger,
