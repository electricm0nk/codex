## `departed_covered_count` — id-level re-derivation, same methodology as repin 3

```
$ python3 -c "
import json
old=json.load(open('<repin-3-committed ledger.json, via git show 5ed69f29f:...>'))['rows']
new=json.load(open('/tmp/ledger_now.json'))['rows']
old_ids={r['id']:r for r in old}; new_ids={r['id']:r for r in new}
old_only=set(old_ids)-set(new_ids); new_only=set(new_ids)-set(old_ids)
common=set(old_ids)&set(new_ids)
changed=[(i,old_ids[i]['join_status'],new_ids[i]['join_status']) for i in common if old_ids[i]['join_status']!=new_ids[i]['join_status']]
print('old_only (departed ids):', len(old_only))
print('new_only (new ids):', len(new_only))
print('common ids with join_status change:', len(changed))
"
old_only (departed ids): 20
new_only (new ids): 7558
common ids with join_status change: 0
```

**Zero common-id regressions** — every id present in both the repin-3 ledger and this repin's ledger
has an unchanged `join_status`. `28490 - 20 + 7558 = 36028` — the population arithmetic checks out
exactly against the id sets, not just the totals.

Of the 20 departed ids:


`ultimate_magic`/`advanced_players_guide`/`ultimate_intrigue` (magus/antipaladin/vigilante) rows,
all `no_formula_tokens` → `text-complete`. All 15 were NOT `no_record` when they left, so they are
the `departed_covered_count` credit — same rule repin 3 established: a completed unit that was
`matched`/`no_formula_tokens` shrinks `population` without shrinking `no_record`, which is real
progress, not drift.

**The 5 absent departures** are all `class_feature`, id-churned by the CATEGORY:-based identity fix

construction, needs no separate credit.

**Arithmetic check:** `no_record` delta (7553) − population delta (7538) = **15**, exactly the
`departed_covered_count` derived above. `BudgetProvenanceTest.test_no_record_delta_never_exceeds_population_delta`'s
