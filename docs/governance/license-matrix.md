# License Matrix — per-book OGL/attribution/PI-screening evidence

**Status:** gate document, operator-authorized 2026-08-10, ahead of the move from
book-scoped to kind-scoped ingestion packages. Territory: `docs/governance/` only —
does not touch `docs/release/SD-29-*`/`SD-30-*` or `corpus-work-channels.md`.

**This matrix inherits `docs/governance/ogl-pi-blacklist.md`'s own stated limit and
must not be read past it.** That module's 54-term blacklist (`pi_screening.rs`) is
*"a bounded, documented heuristic, not an exhaustive legal review."* Nothing below is
legal clearance. It is a record of what each book's own files say about its license,
and whether the pipeline that turned that book into engine data ever checked it.

## Why this exists

Book-scoped packages made license discovery an accident of workflow: someone opened
UPsi's directory to ingest it and happened to notice `ISOGL:YES` and a real 90-line
`OGL.txt`; someone opened UC's directory and happened to notice its declared
`EXTRAFILE:OGL.txt` names a file that does not exist, recoverable only from the
`.pcc`'s own `COPYRIGHT` block. Under kind-scoped packages (one kind, all 37 books,
one pass) nobody ever opens book 30's directory for its own sake. This matrix
converts license discovery from an emergent side effect into a checked precondition
that exists once, up front, instead of never.

## Methodology

- **Book list**: every book id in `docs/work-inventory.json` except `beginner_box`
  (excluded per the operator's own book-scope ruling — a genuinely simplified intro
  subset, not part of this matrix's 37). Derived by command, not transcribed:
  `python3 -c "import json; d=json.load(open('docs/work-inventory.json')); print(sorted(set(b['id'] for b in d['books'])))"`,
  37 remain after dropping `beginner_box`.
- **Publisher**: `PUBNAMELONG:` read directly from each book's own `.pcc` file at
  `~/workspace/repos/pcgen/data/pathfinder/`, not inferred from its directory path.
- **OGL declaration mechanism**: checked in this order per book — a real `OGL.txt`
  file in the book's directory; the `.pcc`'s own `COPYRIGHT:` lines (which are the
  book's section-15-shaped attribution text, present even when no separate file
  exists); `ISOGL:YES`; `#EXTRAFILE:OGL.txt` (a declaration that a file exists,
  checked against the filesystem rather than trusted).
- **PI-screening status**: traced to the actual Rust code that turned each book's
  corpus rows into engine data, not assumed from the book's category. See
  "The central finding" below — this is where the real risk sits.

## The central finding: two pipelines, one ever screened

This codebase generates engine content two structurally different ways, and **only
one of them has ever called a Product-Identity screen.**

**Pipeline A — the JSON corpus cache** (`data/corpus/<book>/<kind>/*.json`, Shape B
v1), written by five generator binaries/modules: `sd26_gen_core_rulebook_cache.rs`
(CRB), `cache_gen::{acg, apg, beastiary1}` (ACG/APG/Bestiary 1), `sd27_gen_book_cache.rs`
(ARG, PU — carries its own inline PI-blacklist fork, the third of the three forks
`pi_screening.rs`'s own doc comment names), and `ingest_race_traits.rs`/
`ingest_pu_classes.rs`/`ingest_races.rs`. Per `pi_screening.rs`'s own header, **three
of these five writers originally shipped with no screening at all** (CRB, and the
ACG/APG/Bestiary-1 trio) — their `license`/`pi_field`/`pi_marker` fields exist today
only via a later retrofit pass the generator itself knew nothing about at write time.
**Six books total ever pass through Pipeline A with any screening, retrofitted or
native: CRB, APG, ACG, Bestiary 1, ARG, PU.**

**Pipeline B — the `rules_tables/*.rs` Rust literal tables**
(`equipment_tables.rs`, `feat_tables.rs`, `archetype_tables.rs`, spell lists, etc.),
generated by ad-hoc per-book Python extraction scripts throughout the SD-27/SD-28
sessions — the pipeline every book ingested this bundle (UI, UE, UM, UPsi, UC, UW,
UCA, and every future-state book still to come) is delivered through, and increasingly
the pipeline the *original six* books' newer content (archetypes, equipment) is
*also* delivered through. **Grepped directly: zero files under `rules_tables/`
reference `pi_screening`, `PI_BLACKLIST_TERMS`, or `classify_field`.** Confirmed by
listing every file in the repo that imports the module at all — eight files, all of
them Pipeline A generators or their direct callers; none of them a `rules_tables/`
table.

**This is not a theoretical gap.** A direct substring sweep of every `rules_tables/*/*.rs`
file against the 55-term blacklist (including `pi_screening.rs`'s own "Jarn" entry)
found real, unredacted hits reaching committed source, none of them screened at
generation:

| file | term | context | note |
|---|---|---|---|
| `acg/archetype_tables.rs` | `Sarenrae` | "...an ecclesitheurge of Sarenrae with Glory..." | real deity name, unscreened, in ACG's *own* newer archetype table — the same book whose JSON cache is one of the six screened |
| `advanced_race_guide/archetype_tables.rs` | `Asmodeus` | "...if she worships Asmodeus or an archdevil..." | real deity name, unscreened, same shape |
| `acg/spell_list.rs` | `Jarn` | "...the target's father's name is Jarn..." | the **exact instance already named** in `pi_screening.rs`'s own doc comment as the reason "Jarn" was added to the shared blacklist — that redaction was applied to the JSON-cache copy of this record, but this Rust-literal `spell_list.rs` copy of the same content was never touched by it and still carries the name in the clear |
| `ultimate_magic/equipment_tables.rs` | `Geb` | "The Formulae of Master **Gebr**" | **false positive** — the blacklist term "Geb" (a place name) substring-matches inside the unrelated proper noun "Gebr"; recorded here as a concrete illustration of the blacklist's own stated bluntness, not a real PI leak |

Three real leaks, one instructive false positive, found by a five-minute sweep of a
55-term list against files nobody had screened. **This is the finding the matrix
exists to surface, not a defect to fix here** (per instruction — recorded, not
patched).

## Unestablished: 1 of 37

**`core_essentials`.** Its own `.pcc` (`paizo/roleplaying_game/core_essentials/_core_essentials.pcc`)
carries `PUBNAMELONG:Paizo Inc.` active, but every `#ISOGL:YES` and every
`#COPYRIGHT:` line is prefixed `#` — commented out, not merely absent. Read at face
value, this book's own file makes no active OGL declaration at all.

Checked whether this is recoverable rather than concluding it is missing (the same
discipline that resolved Ultimate Combat's case): `core_rulebook.pcc` line 43 reads
`PCC:@/pathfinder/paizo/roleplaying_game/core_essentials/_core_essentials.pcc` — a
direct, unconditional inclusion. `core_essentials` is never loaded standalone in this
corpus; it is always pulled in through Core Rulebook, which carries its own real,
active `ISOGL:YES` and `COPYRIGHT:` block. So `core_essentials`'s license is
**practically recoverable via the including `core_rulebook.pcc`'s own active
declaration**, not missing outright — but its own file, read alone, establishes
nothing, which is why this row is marked unestablished rather than silently resolved
to "same as Core Rulebook." A future book onboarded to reference `core_essentials`
data by any path other than the Core Rulebook inclusion would need its own
declaration, and none exists to fall back on.

## What surprised me

1. **The two-pipeline split, and that it is not a settled-vs-new-book distinction.**
   Expected the split to run along "old books screened, new books not." It instead
   runs along "content generated as JSON corpus cache vs. content generated as a Rust
   literal table" — and even the six *screened* books have *unscreened* content the
   moment their newer material (ACG's/ARG's own archetype tables, both landed this
   session) went through Pipeline B instead. Screening a book once does not keep it
   screened as more content lands for it through a different pipeline.
2. **The `Jarn` re-leak.** `pi_screening.rs`'s own doc comment names this exact NPC
   name as a real hit found and redacted in ACG's JSON-cache record. The identical
   content exists a second time, unredacted, in `acg/spell_list.rs` — a retrofit
   fixed the artifact someone was looking at and never touched the parallel one
   nobody was.
3. **How close the numbers ran otherwise.** 36 of 37 books have a real `OGL.txt`,
   real `ISOGL:YES`, and a real `.pcc` COPYRIGHT block — the license-declaration
   half of this matrix is in genuinely good shape. The screening half is not: 31 of
   37 books (84%) have never had a single record checked against the blacklist at
   generation time, and the three real leaks found in a five-minute sweep suggest
   more exist unfound in the other ~4,700 archetype/equipment/feat records this
   session alone landed through Pipeline B.

## Addendum 2026-08-11 — the Pipeline B screen now exists (SD-29 Epic 3)

The "Not fixed here" section below stands as authored: **no redaction was applied** and
none of the three real leaks it names was touched — those tables are owned by the bundles
that wrote them, not by SD-29. What changed is the thing that section named as the likely
next prerequisite: *"wiring `pi_screening::classify_field` into the extraction scripts that
write `rules_tables/*.rs`, before any kind-scoped package runs against a book that has never
passed through it."*

- `src/rules_core/pi_table_sweep.rs` runs the shared `pi_screening::PI_BLACKLIST_TERMS`
  list (it does not fork it) over Pipeline B. `screen_generated_table()` is the lane-facing
  call an extraction step makes on generated table text **before** it writes; a hit is a hard
  stop for that record per `SD-29 decisions.md §37.3` / `AT-29-003a`.
- `src/bin/pi_sweep_rules_tables.rs` is the standing sweep, wired as the `pi-sweep` stage of
  `scripts/verify.sh` (in **both** the full and `--quick` sets) and asserted by
  `tests/pi_table_sweep.rs` on every `cargo test`.
- `docs/governance/pi-sweep-baseline.tsv` carries the pre-existing hits with an explicit
  `real-leak`/`false-positive` disposition. The gate fails on any hit the baseline does not
  account for **and** on any baseline row the tree no longer carries, so the file cannot decay
  into a blanket suppression.

**Correction to this matrix's own sweep, re-derived 2026-08-11** by
`cargo run --locked --bin pi_sweep_rules_tables` over 137 files / 55 terms: the tree carries
**10** hits, not the 4 this matrix's five-minute manual sweep reported. The three real leaks
are exactly as recorded. The false-positive count is **7**, not 1: besides `Geb`/"Gebr", the
term `Nex` substring-matches the spell name **"Discern Next of Kin"** in six spell-list tables
(`acg/shaman_spell_list.rs`, `acg/spell_list.rs`, `apg/witch_spell_list.rs`,
`crb/bard_spell_list.rs`, `crb/sorcerer_spell_list.rs`, `crb/wizard_spell_list.rs`) — the same
record whose flavor text carries the `Jarn` re-leak. No new *real* leak was found; the
correction is to the count and to the blacklist's demonstrated bluntness, both now pinned by a
committed baseline rather than a prose estimate.

## Not fixed here

Per instruction, nothing above was corrected. No redaction applied, no `pi_screening`
call added to any Pipeline B script, no `OGL.txt` reconstructed for Ultimate Combat.
This is a record for the operator's own disposition — including whether the next
prerequisite work is wiring `pi_screening::classify_field` into the extraction
scripts that write `rules_tables/*.rs`, before any kind-scoped package runs against
a book that has never passed through it.
